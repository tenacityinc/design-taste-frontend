## 1. Caption overlay window

### Window setup (Electron)
```js
new BrowserWindow({
  width: 900, height: 220, minWidth: 480, minHeight: 140,
  frame: false, transparent: true, resizable: true,
  alwaysOnTop: true, skipTaskbar: true, hasShadow: false,
});
win.setAlwaysOnTop(true, 'screen-saver');        // stays above full-screen call apps
win.setVisibleOnAllWorkspaces(true, { visibleOnFullScreen: true });
```
- **Drag handle:** a 24px strip at the top with `-webkit-app-region: drag`. Every control is `no-drag`.
- **Click-through mode** is optional. `setIgnoreMouseEvents(true, { forward: true })` lets clicks reach the call app underneath. Turn it off when the pointer enters the control bar, so the controls still work.
- **Save** position, size and settings with `electron-store`, and restore them on launch.

### Layout
```
┌──────────────────────────────────────────────────────────┐
│ ⠿ drag        ● Live              [⏸ Pause]  [Aa]  [⤢]  │  ← control bar (fades when idle)
├──────────────────────────────────────────────────────────┤
│ ▌Priya   …so the release moves to Thursday, and we       │  ← older line (secondary ink)
│ ▌Priya   need QA sign-off by Wednesday noon.             │
│ ▌You     Okay, I'll ping the QA channel now ▁            │  ← newest line; unfinished words lighter
└──────────────────────────────────────────────────────────┘
```

**Caption text area**
- Show 2–4 lines (user setting) and roll upward. Never scroll inside the box, and never jump.
- Cap line length at about 42 characters (`max-width: 42ch`), the usual broadcast-caption limit, so the eye doesn't have to travel far.
- Draft vs final words: while the recognizer is still guessing, show the unfinished words in secondary ink at the same weight and size. Swap to primary ink when the text is final. Don't use italics, and don't change size or weight, because those reflow the line and make it jitter.
- Reserve space for the full line height, so text that gets corrected doesn't push the lines above it around.
- Font is `system-ui` at weight 500, line-height 1.35, default 28px.
- Use `aria-live="off"` by default, since the users read the captions rather than listen to them. Add a setting for screen-reader users that switches it to `polite` and announces only final words.

**Speaker labels**
- Put the speaker name in a fixed-width column on the left (`grid-template-columns: 9ch 1fr`). Long names get cut off with an ellipsis, and the full name shows on hover.
- Each speaker gets a 4px colored bar (`▌`) next to their name. The name itself stays in normal text color, so the bar is extra and color never carries identity on its own.
- Assign speaker colors in arrival order from the fixed palette on the dark surface (`#3987e5`, `#d95926`, `#199e70`, `#c98500`, …). Never reassign a color once given. From the 5th speaker on, use a neutral gray bar and rely on the name alone.
- When the speaker changes, start a new line with the label. While the same speaker continues, leave the label column blank.
- If diarization (working out who is speaking) isn't confident, show "Speaker 2" rather than guessing a name.

**Pause and resume**
- Use one toggle button with an icon and a text label: `⏸ Pause` / `▶ Resume`. Also bind a global shortcut (`globalShortcut`, e.g. ⌘⇧P).
- **Paused must never look like silence.** While paused, show a full-width banner, "Captions paused · 0:42", with the bar's status dot switched to a hollow ○, and leave the last caption text visible but dimmed to 50%.
- Keep three states visually distinct, each with an icon and label: **Live** ●, **Paused** ○, and **Reconnecting** ⟳. Reconnecting uses the warning color plus its text label.
- The control bar fades to 0 after 3 seconds without the pointer over it. It always reappears on hover or keyboard focus, and it never fades while paused.

**Settings panel** (popover from the `Aa` button, about 280px wide, inside the overlay)
| Control | Type | Range / options |
|---|---|---|
| Font size | Slider + −/+ buttons, live preview | 18–56px, step 2 |
| Lines visible | Segmented control | 2 / 3 / 4 |

| Background opacity | Slider | 60–100% (locked to 100% in High) |
| Speaker colors | Toggle | on/off |

- The renderer applies settings as CSS variables on `:root`. Nothing is styled per element.
- Follow the `forced-colors: active` media query: switch to system colors and drop the speaker bars, leaving names only.

```css

}

**Charts**
- **Two separate charts, never one chart with two y-axes.** Milliseconds and percentages on a shared plot would suggest a correlation that isn't in the data. Stack the two charts with identical x-axes (last 60 minutes, ticks every 10 minutes) and a **synced hover line**: hovering minute 14:32 in one chart shows it in both. **uPlot** handles this well (`cursor.sync`). It's small, fast for live time series, and is canvas-based, so add your own table/ARIA layer for accessibility.
- **Latency:** p50 uses color slot 1 (blue `#2a78d6` light / `#3987e5` dark) and p95 uses slot 2 (orange `#eb6834` / `#d95926`). Lines are 2px. Show a legend, and label each line's last point directly ("p95 1.24 s"). The 1500 ms target is a labeled hairline in muted ink, not a status color.
- **WER:** a single line in slot 3 (aqua `#1baf7a` / `#199e70`), so it doesn't reuse a color that means "p50" in the chart above. The chart title names it, so it needs no legend. Light-mode aqua is below 3:1 contrast, so it must keep its last-point label, with the table as backup.
- **Paused time:** break the line (store `null`, don't interpolate) and shade that stretch with a light gray band labeled "Paused".
- **Chrome:** solid hairline gridlines (`#e1e0d9` / `#2c2c2a`), never dashed. Axis text is muted `#898781` with `tabular-nums`. Chart surface is `#fcfcfb` / `#1a1a19`. The chart container's height must include the x-axis labels so the card never scrolls internally.
- **Tooltip:** shows time, p50, p95 and WER together. Keyboard: the arrow keys move the hover line minute by minute.
- **Live refresh:** add a new point each minute without redrawing from scratch. During a refetch, keep the old chart at 60% opacity rather than flashing a loading skeleton.

**Table**
- 1-minute buckets, newest first. Numeric columns are right-aligned with `tabular-nums`.
- A **Status** column uses status colors only for actual status, always with an icon and word: `✓ OK`, `▲ Slow` (p95 > target), `✕ High WER`. Never color a row by itself.
- The table is the accessible version of both charts, so every value can be reached without a tooltip.

**Summary tiles:** the big numbers use normal proportional digits (not `tabular-nums`) in the system sans, with the change vs the previous hour shown as an arrow, the value and a sign, e.g. "▼ 0.12 s".

## Caption text area

- **Readability first.** Default font size is 28px, adjustable from 18 to 56px. Line height 1.45, `max-width: 60ch` (centered when the window is wide), weight 500, system sans. Never use thin weights, because they break up over video backgrounds.
- **Interim vs. final text.** Final words use primary ink. The interim tail uses secondary ink with a trailing `…`. Avoid italics, which hurt readability at speed. When the text finalizes, swap the color in place and don't re-layout, so the words don't jump.
- **Append-only with stable scroll.** Auto-scroll to the bottom only while the user is already at the bottom. If they scroll up to re-read, freeze the view and show a "Jump to live" pill. Keep about 200 turns in the DOM and trim older ones.
- **Background.** A solid panel at 88–92% opacity, never fully transparent. Captions over arbitrary video fail contrast. The high-contrast mode is 100% opaque.
- **Accessibility markup.** Use `role="log"` with `aria-live="off"` on the stream, since a screen reader announcing every interim word is noise. Expose a separate "read last turn" command.

## Speaker labels

- Each turn starts with a **name label**: 0.6× the caption size, weight 600, uppercase tracking off. Add a **4px colored bar** down the left edge of the turn.
- **Color is never the only signal.** The name text always appears, and the bar is just a second cue.
- **Color follows the speaker, not their order.** Assign colors from a fixed categorical order (blue, orange, aqua, …) on each speaker's first appearance and keep that mapping for the whole call. Someone leaving must not cause anyone else's color to change. From the 9th speaker on, everyone gets a neutral gray bar, and the name carries the identity.
- **"You"** always gets a neutral ink bar so your own speech is easy to skip past.
- **Unknown speaker:** "Speaker 2" with a gray bar. When diarization later names them, relabel the existing turns.

## Pause and resume

- The header's left side shows **state plus action** together: `● LIVE` (red dot with the text label) and a `❚❚ Pause` button. When paused, it shows `❚❚ PAUSED · 14 new lines` and a `▶ Resume` button.
- **Pausing freezes the display, not the capture.** Transcription keeps buffering, and Resume jumps to live, so nothing is lost. Make this explicit in the tooltip: "Pausing freezes the view; captions keep recording."
- Whenever the view is paused, a 2px amber top border plus the PAUSED label makes it impossible to mistake a frozen view for silence.
- Buttons have a 32px minimum hit target and a visible `:focus-visible` ring (2px, offset 2px).

## Caption text area

- **Readability first.** Default font size is 28px, adjustable from 18 to 56px. Line height 1.45, `max-width: 60ch` (centered when the window is wide), weight 500, system sans. Never use thin weights, because they break up over video backgrounds.
- **Interim vs. final text.** Final words use primary ink. The interim tail uses secondary ink with a trailing `…`. Avoid italics, which hurt readability at speed. When the text finalizes, swap the color in place and don't re-layout, so the words don't jump.
- **Append-only with stable scroll.** Auto-scroll to the bottom only while the user is already at the bottom. If they scroll up to re-read, freeze the view and show a "Jump to live" pill. Keep about 200 turns in the DOM and trim older ones.
- **Background.** A solid panel at 88–92% opacity, never fully transparent. Captions over arbitrary video fail contrast. The high-contrast mode is 100% opaque.
