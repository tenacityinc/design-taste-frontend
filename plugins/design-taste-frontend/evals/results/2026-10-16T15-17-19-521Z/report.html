## 1. Caption overlay window

### Window (main process)
```js
new BrowserWindow({
  width: 900, height: 220, minWidth: 480, minHeight: 140,

### Caption text rules
- **Measure:** `max-width: 42ch` (the broadcast caption standard). Show 2–3 lines and scroll older lines up. Don't animate the scroll when `prefers-reduced-motion` is set.
- **Final vs. interim:** final words use primary ink. Interim words, which may still change, use secondary ink at the same weight. Don't use italics; they're harder to read at a glance. When interim text is confirmed, only its color changes. Words never move, because text that reflows mid-sentence is the biggest readability problem in live captions.
- **Font:** system sans, weight 500, `line-height: 1.35`, `letter-spacing: 0.01em`. Size steps are **20 / 24 / 28 (default) / 34 / 40 / 48 px**.

### Speaker labels
- Show the label only when the speaker changes, not on every line.
- **The name is always text**, in primary ink and weight 600. Each speaker also gets a 4px colored bar (`.speaker-key`) on the left of their block. Color is a second cue, never the only one, so the overlay works for colorblind users and in high-contrast mode.
- Assign colors by speaker identity, in join order, using fixed slots that are never cycled. Blue, orange and aqua stay distinguishable in both light and dark modes. From the fourth speaker on, the bar is a neutral gray and only the name identifies them. A speaker keeps their color for the whole call even if others leave.
- Unknown speakers show as "Speaker 1", "Speaker 2", and so on, never as a blank.

### Pause / resume
- **Recommended behavior:** pause freezes the display so the user can read, while capture keeps running in the background. Resume shows a "**Jump to live**" button with a count ("+6 lines"). Pausing to catch up is the main reason a hard-of-hearing user presses it. If you also need a mode that stops recognition entirely, put it in settings as "Stop captioning".
- The button is at least 44×44 px and always shows an icon plus a word ("Pause" / "Resume"). While paused, a status pill reads "⏸ Paused", alongside a 2px amber inset border on the window. The text carries the state, not the color.
- The control bar fades in on hover or keyboard focus and fades out after 3 s. It stays visible while paused or while settings are open.

### Settings panel
A small popover anchored to ⚙, about 280px wide:
- **Text size:** a segmented control with the six steps, previewed live on the overlay.
- **Contrast:** radio cards, each showing a preview swatch:
  - *Standard*: near-black panel at 85% opacity, off-white text
  - *High*: solid `#000` and `#fff`, interim text `#d0d0d0`, no transparency
  - *Yellow on black*: `#ffd60a` on `#000`, a common caption preference
  - *Light*: off-white panel with dark text, for bright rooms
- **Background opacity:** slider from 60–100%. It's disabled in High mode.
- **Show speaker names:** toggle.

## 2. Data dashboard (a normal window, not the overlay)

### Form decisions
- **Two separate charts, not one dual-axis chart.** Latency (ms) and WER (%) are on different scales. Putting them on two y-axes invites false correlation. Instead, stack the two charts at the same width so their time axes line up, and link their crosshairs.
- **Stat tiles above the charts:** latency p50, latency p95, and WER over the last hour. Each tile shows the change against the previous hour, with an icon and a sign so it isn't color alone. Down is good for both metrics, so a drop shows as good.
- **Table below the charts:** this is the exact-values view and the screen-reader view.

### Layout
```
┌ Caption quality · Last hour ▾ ─────────────────── [Live ●] ┐
│ ┌ Latency p50 ┐ ┌ Latency p95 ┐ ┌ Word error rate ┐       │
│ │ 640 ms ▼8%  │ │ 1.42 s ▲3%  │ │ 6.1 %  ▼0.4 pt  │       │
│ └─────────────┘ └─────────────┘ └─────────────────┘       │
│ Caption latency (ms)                 ── p50  ── p95       │
│ [line chart, 60 × 1-min buckets, 2s target hairline]      │
│ Word error rate (%)                                       │
│ [line chart, same x-axis, crosshair linked]               │
│ ▸ Per-minute data (60 rows)   [Copy CSV]                  │
│ Time  │ p50 ms │ p95 ms │ WER % │ Words │ Status          │
└───────────────────────────────────────────────────────────┘
```
CSS grid: `grid-template-columns: repeat(3, minmax(0,1fr))` for the tiles, then each chart spans the full width at about 200px tall, then the table. Leave 24px between sections and 16px padding inside cards.

### Chart specs
- **Latency chart:** two series. p50 is blue (`#2a78d6` light / `#3987e5` dark) and p95 is orange (`#eb6834` / `#d95926`). Because there are two series, it gets a legend, plus labels at the end of each line. Add a 1px muted reference line at the latency target labeled "2 s target" in muted ink. Don't use a status color for the target line.
- **WER chart:** one series in blue. The title names it, so it needs no legend. Start the y-axis at 0% and leave the top on auto.
- **Marks:** 2px lines with round joins, an 8px end dot with a 2px ring in the surface color, and an optional 10% opacity area wash under p50 only. Gridlines are 1px solid hairlines (`#e1e0d9` light / `#2c2c2a` dark). Axis ticks use muted ink with `tabular-nums`: x-axis every 10 minutes (`14:10`), y-axis rounded (`0 / 500 / 1,000`).
- **Gaps:** when a minute has no captions (silence), break the line. Don't connect across the gap or draw zero.
- **Hover:** a vertical crosshair snaps to the nearest minute. The tooltip shows the time and every value at that minute, using text-colored values next to small color keys. Hovering one chart moves the crosshair on the other. Arrow keys move the crosshair once a chart has focus.
- **Text never uses the series color.** Labels, values and the legend use primary, secondary or muted ink. Identity comes from the colored line or dot next to the text.
- **Dark mode** uses the dark color values listed above against a `#1a1a19` surface. Set it with `data-theme` and also respect `prefers-color-scheme`.

### Table
- One row per minute, newest first. Columns: Time, p50 ms, p95 ms, WER %, Words, Status.
- Numbers are right-aligned with `tabular-nums`. The header is sticky.
- Status shows as an icon plus a word ("✓ OK", "⚠ Slow", "✕ Degraded"), with status colors applied only to the icon.
- The table is collapsed by default, with a "Copy CSV" button.

### Data plumbing
The main process aggregates recognizer events into 1-minute buckets in a 60-slot ring buffer. Each bucket holds the p50 and p95 latency (from the gap between audio timestamp and render) and WER. Measuring WER needs reference transcripts, so in production you'll probably have user corrections or sampled audits rather than true WER. Label the chart honestly, e.g. "Estimated WER (from corrections)". The main process sends a snapshot over IPC once a minute and streams the current partial bucket every 5 s.

For the charts, uPlot is small and fast and can redraw every second. Recharts is fine if the dashboard is in React. Either way, keep the color and size values in CSS custom properties, not inside the chart code.

## Caption text: decisions specific to hard-of-hearing users

- **Show 2–3 lines, newest at the bottom.** The container is `display:flex; flex-direction:column; justify-content:flex-end; overflow:hidden`. Older turns scroll up and out of view but stay in the DOM so the user can scroll back.
- **Words never move once displayed.** Finalized words are append-only. Only the interim tail (`.interim`) may be rewritten as the ASR revises it. Words that jump around are the most common complaint about live captions.
- **Interim vs. final.** Interim text uses the secondary ink color, not italics, so it doesn't jitter or shift layout. When it's finalized it switches to primary ink with no animation.
- **Typography.** System sans (`system-ui, -apple-system, "Segoe UI"`), weight 500, `line-height: 1.4`, `max-width: 60ch` per line. Never use all-caps. Use `text-wrap: pretty` so lines don't end on a single orphaned word.
- **Motion.** Scrolling eases over 120ms. Under `prefers-reduced-motion` it snaps instantly.
- **Screen readers.** `aria-live` is off by default, because reading every interim update aloud is noise. Offer a "Announce finalized captions" setting for DeafBlind users on braille displays. When it's on, use `aria-live="polite"` on finalized text only.

## Speaker labels

- Each speaker gets a **name label plus a 4px colored bar** (`.key`) at the start of their turn. The name text always uses primary ink, never the speaker color. That way the name carries identity and the color is only a reinforcement.
- **Colors are assigned in the order speakers join, then stay fixed.** If someone leaves, the others keep their colors. Use the fixed categorical order (blue → orange → aqua → yellow → magenta → green → violet → red). Never cycle back to the start. A 9th speaker gets a neutral gray bar; their name is still shown.
- A new speaker always starts a new block. If the same speaker keeps talking, their text continues in the same block, with no repeated label.
- **Unknown speakers** are labeled "Speaker 3" and the user can rename them inline. Unidentified speech with no diarization shows no label at all, rather than a misleading one.

## Pause / resume

Pausing should **freeze the display, not stop transcription.** Users pause to re-read something they missed. They don't want to lose what's said in the meantime.

- **While paused:** the view stops auto-scrolling and the user can scroll back freely. Captions keep buffering. The status dot reads "Paused" with a pause icon (not color alone). A badge shows "Paused · 6 new lines · Resume ▸".
- **Resume** jumps to the live edge.
- **Scrolling up pauses automatically.** Scrolling to the bottom resumes. Keyboard: Space toggles pause, Esc resumes.
- If you also want a real "stop transcribing" (for privacy), make it a **separate** control with a distinct icon and label, so users can't confuse the two.

## Caption text: decisions specific to hard-of-hearing users

- **Show 2–3 lines, newest at the bottom.** The container is `display:flex; flex-direction:column; justify-content:flex-end; overflow:hidden`. Older turns scroll up and out of view but stay in the DOM so the user can scroll back.
- **Words never move once displayed.** Finalized words are append-only. Only the interim tail (`.interim`) may be rewritten as the ASR revises it. Words that jump around are the most common complaint about live captions.
- **Interim vs. final.** Interim text uses the secondary ink color, not italics, so it doesn't jitter or shift layout. When it's finalized it switches to primary ink with no animation.
- **Typography.** System sans (`system-ui, -apple-system, "Segoe UI"`), weight 500, `line-height: 1.4`, `max-width: 60ch` per line. Never use all-caps. Use `text-wrap: pretty` so lines don't end on a single orphaned word.
- **Motion.** Scrolling eases over 120ms. Under `prefers-reduced-motion` it snaps instantly.
- **Screen readers.** `aria-live` is off by default, because reading every interim update aloud is noise. Offer a "Announce finalized captions" setting for DeafBlind users on braille displays. When it's on, use `aria-live="polite"` on finalized text only.

## Speaker labels

- Each speaker gets a **name label plus a 4px colored bar** (`.key`) at the start of their turn. The name text always uses primary ink, never the speaker color. That way the name carries identity and the color is only a reinforcement.
- **Colors are assigned in the order speakers join, then stay fixed.** If someone leaves, the others keep their colors. Use the fixed categorical order (blue → orange → aqua → yellow → magenta → green → violet → red). Never cycle back to the start. A 9th speaker gets a neutral gray bar; their name is still shown.
- A new speaker always starts a new block. If the same speaker keeps talking, their text continues in the same block, with no repeated label.
- **Unknown speakers** are labeled "Speaker 3" and the user can rename them inline. Unidentified speech with no diarization shows no label at all, rather than a misleading one.

## Pause / resume

Pausing should **freeze the display, not stop transcription.** Users pause to re-read something they missed. They don't want to lose what's said in the meantime.

- **While paused:** the view stops auto-scrolling and the user can scroll back freely. Captions keep buffering. The status dot reads "Paused" with a pause icon (not color alone). A badge shows "Paused · 6 new lines · Resume ▸".
- **Resume** jumps to the live edge.
- **Scrolling up pauses automatically.** Scrolling to the bottom resumes. Keyboard: Space toggles pause, Esc resumes.
- If you also want a real "stop transcribing" (for privacy), make it a **separate** control with a distinct icon and label, so users can't confuse the two.
